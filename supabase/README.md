# Сбор заявок на ранний доступ через Supabase

Лендинг — статическая страница на GitHub Pages, поэтому форма пишет напрямую
в Supabase через REST API с публичным (anon) ключом.

## Как устроено

- `waitlist` — таблица заявок. RLS включён, политик нет: anon-ключ не может ни
  читать, ни писать в таблицу напрямую. Читаете вы через Dashboard / Table Editor.
- `join_waitlist(email, source, utm, referrer)` — единственная функция, доступная
  anon-ключу. Она приводит адрес к нижнему регистру, проверяет формат и
  игнорирует повторную отправку того же адреса (без ошибки для пользователя).
- Поля `status` и `note` — для вашей работы с заявками (кого позвали, кто ответил).

## Подключение

1. Выполните `migrations/0001_waitlist.sql` в SQL Editor проекта Supabase.
2. В Dashboard → Project Settings → API скопируйте Project URL и anon public key.
3. В `index.html` заполните константы `SUPABASE_URL` и `SUPABASE_ANON_KEY`
   в блоке `<script>` внизу файла.

Anon-ключ в HTML — это нормально: он рассчитан на публичное использование,
а доступ ограничен тем, что разрешено функции `join_waitlist`.

## Что отправляет форма

```json
{ "p_email": "a@b.ru", "p_source": "landing-beta",
  "p_utm": { "utm_source": "tg" }, "p_referrer": "https://t.me/..." }
```

## Что проверить после подключения

- Отправить тестовый адрес на сайте → строка появилась в `waitlist`.
- Отправить тот же адрес ещё раз → на сайте «Спасибо», строка не дублируется.
- Открыть сайт с `?utm_source=test` → в колонке `utm` появился JSON.
